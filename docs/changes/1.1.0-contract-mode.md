# ai-team-sdlc 1.1.0 — Change specification (v3)

**Scope:** contract mode, reviewer independence, repo rules and model flexibility.
**Target repo:** `CalinL/ai-team-sdlc` (public). **Base:** release 1.0.4 = commit `4223b6e` (there is no `v1.0.4` tag; the latest tag is `1.0.2`). **New version:** 1.1.0.
**Audience:** whoever implements the change (a person or an agent in a fresh session). Everything needed is in this file and the target repo. All plugin paths are relative to `plugins/ai-team-sdlc/` unless they start with `docs/`, `.github/` or are root files (`AGENTS.md`, `README.md`).

---

## 0. What this release does, and what it must never break

The plugin today runs a complete lifecycle on its own: design → prototype → PRD → spec → build → test → sign-off → deploy. Some teams already own requirements and architecture elsewhere, and want this team only for **delivery**: slicing existing requirements into stories, a prototype kept as the UI spec, implementation, testing and release, under their architecture governance.

| # | Feature | Default behavior after the release |
|---|---|---|
| G1 | **Host repo rules + safety floors:** agents read the host repo's `AGENTS.md` / `.github/copilot-instructions.md`; a fixed list of safety floors can't be overridden | Changed (beneficial): agents follow host workflow rules. Sign-off and gates can't be weakened |
| G2 | **No model pins:** agents use the host's normal model resolution | Changed: was always `gpt-5.6-sol` |
| G3 | **Authorship lineage:** tasks record their model(s) and files, when known | Additive: optional fields; no new questions to the user |
| G4 | **Reviewer independence (optional):** the critic review checks that reviewers come from a different model family than the authors | **Unchanged** (off by default) |
| C | **Contract mode (opt-in):** deliver from a brief and existing requirements, under external acceptance gates and an external decision log | **Unchanged** unless the host repo has `.github/ai-sdlc.yml` with a `contract:` block |

**Non-negotiable guarantees**

1. **Without `.github/ai-sdlc.yml`, the lifecycle, artifacts, gates, tracking files, scribe behavior and sign-off are exactly as in 1.0.4**, apart from G1–G3.
2. **All three surfaces keep working:** VS Code Local harness, VS Code Copilot harness, and Copilot CLI.
3. **The safety floors (G1) hold in every mode.**

## 1. Ground rules for implementing this change

### R1. "Add, don't edit": what it means precisely

Existing text is **never rewritten, reworded, reordered or deleted**. New behavior is added in one of these ways only:

| # | Allowed addition | Rule |
|---|---|---|
| A1 | **A new file** | e.g. `skills/ait-contract-mode/SKILL.md` |
| A2 | **A conditional block**, inserted between two existing lines at a named anchor | Starts with the exact heading `### Contract mode (only when .github/ai-sdlc.yml defines contract)`; first line states the condition; last line: "Otherwise ignore this section." |

### R2. Portability: behavior lives in skills

Per the plugin repo's own design (`docs/ai-sdlc-design.md`): only **skills** and **`AGENTS.md`** are read on every surface, so **all behavior goes in skills**. Agent frontmatter changes are limited to fields that work, or are safely ignored, everywhere. Facts (November 2026; sources in Appendix A):

| Field | Copilot CLI | VS Code (plugin agents) | Use in this release |
|---|---|---|---|
| `model` | Optional; omitted → inherits the outer agent's or session model | Optional; omitted → the currently selected model | **Remove** (G2) |
| `include-custom-instructions` | Subagent gets repo instruction files only if `true` (default `false`) | **Not forwarded** for plugin agents | Add as a CLI supplement; the **skill** does the real work (G1) |
| `model-policy` / `modelPolicy` | Supported | **Not forwarded** for plugin agents | **Don't use** |
| `handoffs`, `agents` | Ignored | Local-harness features | **Keep as is** |
| `infer` / `disable-model-invocation` | Both listed | `infer` deprecated | **Don't change** (§8) |

The VS Code editor may show schema hints for fields that belong to another harness (e.g., `handoffs` vs `include-custom-instructions`). That is expected; what matters is that every agent **loads and runs** on each surface.

### R3. One activation switch

Contract mode and reviewer independence are configured in **one optional file in the host repo: `.github/ai-sdlc.yml`** (schema in §4.1). No file means no change. **If the file exists, it is validated, and any error stops the run with the errors listed:** it isn't valid YAML, or a `contract:` or `review:` block breaks the schema. The plugin never silently falls back to default mode.

```markdown
## Reviewer independence (only when .github/ai-sdlc.yml sets review.independence)
Default (no setting, or `off`): skip this section.
When `review.independence` is `warn` or `required`:
1. Compute the lineage of the files under review (`ait-conventions` › Authorship lineage).
   Map each model id to its family by vendor prefix (`gpt-*`/`o*` → OpenAI, `claude-*` →
   Anthropic, `gemini-*` → Google, `grok-*` → xAI; any other prefix is its own family).

   any later change makes it stale.
3. If it is not met: ask the human to re-run this review in a session on a model from a qualifying
   family, and say which families qualify. Do not select or invoke reviewers yourself.
4. Report `independence: met | not_met | unknown`. With `warn`, the critic gate may pass with
   the warning. With `required`, the critic gate fails unless independence is `met`, or a human
   waiver for this artifact version is recorded in `decisions.md`.
```

## 4. Contract mode (opt-in)

### 4.1 Activation, schema and validation

**Active only when `.github/ai-sdlc.yml` has a `contract:` block.** The orchestrator detects it at step 0, validates it, and records `"mode": "contract"` in `state.json`. A phase skill run on its own reads and validates the file directly.

```yaml
# .github/ai-sdlc.yml  (all paths are the host repo's choice)
contract:
  brief: docs/delivery/brief.md        # REQUIRED. The run's spec (owned outside this team)
  requirements: docs/requirements.md   # OPTIONAL. An existing PRD: slice it, never rewrite it
  stages:
    design: false                      # OPTIONAL, default true. false = skip design/ideation
    prototype: ui-spec                 # OPTIONAL, default spike. ui-spec = keep as the UI spec
  paths:                               # OPTIONAL. Where deliverables go (tracked)
    stories: docs/delivery/stories.md
    prototype: docs/delivery/prototype/
    specs: docs/delivery/specs/
    results: docs/delivery/results/
  decisions:                           # OPTIONAL. An external decision log
    dir: docs/adr/
    proposed_status: Proposed          # specialists may only ADD new records with this status
    accepted_status: Accepted          # only humans set this
  protected: [docs/architecture/]      # OPTIONAL. Never edited by the team
  frozen: [tests/contract/]            # OPTIONAL. Never edited (e.g. an agreed evaluation set)
  path_check: scripts/check-paths.sh   # OPTIONAL. Extra check command; non-zero exit = fail
  external_gates:                      # OPTIONAL. Human acceptance files (schema below)
    - id: prototype-accepted
      before: specs                    # one of: stories | prototype | specs | build | signoff
      file: docs/delivery/prototype/ACCEPTED.md
    - id: spec-conformance
      before: build
      file: docs/delivery/conformance/{spec}.md
    - id: release-acceptance
      before: signoff
      file: docs/delivery/results/acceptance-{version}.md
review:                                # OPTIONAL (G4); works with or without contract
  independence: off                    # off | warn | required
```

**Validation:** if the file exists but isn't valid YAML, stop. When `contract:` exists: `brief` is present and readable; every listed path is relative to the repo root and has no `..`; `stages.prototype` ∈ {`spike`, `ui-spec`}, and `paths.prototype` is **required** when it is `ui-spec`; `before` ∈ {`stories`, `prototype`, `specs`, `build`, `signoff`}; gate ids are unique. When `review:` exists: `independence` ∈ {`off`, `warn`, `required`}. Any error stops the run with the errors listed. `decisions.dir` is treated as protected, except for adding new Proposed records (§4.2 §10). Unknown keys → warning, ignored.

**Artifact identity (digest).** Acceptance binds to content, not to a label:
- a **file** → the SHA-256 of its bytes, lowercase hex;
- a **folder** → the SHA-256 of a canonical manifest: one line per file, `<path relative to the folder, with '/' separators> <file SHA-256>`, sorted by path (byte order), UTF-8, LF line endings, with a trailing newline. **Excluded from the manifest:** any file matching an `external_gates[].file` (the acceptance receipts themselves), so writing a receipt never changes the digest it records;
- the **release** → the commit SHA of the release candidate. The orchestrator records it in `state.json.signoff.artifact` as soon as Build and Test are green, **before** evaluating `release-acceptance`.

Any change to the content gives a new digest, so an earlier acceptance becomes **stale**.

**Placeholders:** `{spec}` = the file name, without extension, of the implementation spec a build task implements; `{version}` = the release candidate's commit SHA (short form allowed).

**Acceptance file schema** (written by a human, never by the team):

```markdown
---
status: accepted            # accepted | rejected
accepted_by: <name>         # a human
accepted_at: <ISO date>
artifact: <path accepted>
digest: <digest of the accepted artifact, computed as above>
---
<free text: conditions, notes>
```

### 4.2 The new skill: `skills/ait-contract-mode/SKILL.md` (A1)

All contract-mode rules live in this one file; other files point to it.

```yaml
---
name: ait-contract-mode
description: 'Contract mode for the AI-SDLC team: deliver from a brief and existing requirements under an external architecture owner, with a kept UI-spec prototype, human acceptance gates, an external decision log and protected paths. Use only when the host repo has .github/ai-sdlc.yml with a contract block; never otherwise.'
license: Apache-2.0
---
```

Body: these sections, with these rules (write them as the skill's own text):

| § | Section | Rules |
|---|---|---|
| 1 | Activation | Active only when `.github/ai-sdlc.yml` has `contract`. Validate per the schema; on errors, stop and report. Record `mode: contract`. The safety floors in `ait-conventions` always apply |
| 2 | The brief | `contract.brief` is the specs source. Never invent or rewrite it |
| 3 | Requirements and stories | If `requirements` is set, `ait-product-owner` **slices it into stories** in `paths.stories` (default: the tracking store). Each story cites a requirement ID and any decision record it implements, with acceptance criteria. **No new PRD.** If `requirements` is unset, write stories from the brief, still no PRD. If it is set but missing, stop and ask. `spec-review` checks traceability and testability |
| 4 | Flow (architecture-first) | Task kinds, in order: `stories` → `design` (only if `stages.design` is true) → `prototype` (UI work only) → `specs` → `build` → `test` → `signoff` → `deploy`. With `design: false`, the prototype works from the brief, the stories and any design system in the host repo. Re-decompose build and test tasks once the specs pass their gates |
| 5 | Prototype as UI spec | With `stages.prototype: ui-spec`, the output folder is `paths.prototype`. The prototype defines canonical `data-testid` attributes on critical flows. Once its `prototype-accepted` gate is met (§7), it is **kept as the UI specification**; implementation reuses the selectors, and QA re-runs those flows against the build. Any later change to the accepted prototype, including a new `-v<N+1>` created by the user, changes its digest: the gate becomes stale, and specs written against the old digest are flagged for review. It is never shipped as the product. With `spike` or unset, default behavior |
| 6 | Implementation specs | `ait-architect` writes specs to `paths.specs`, against the stories and the accepted prototype. In contract mode it does not dispatch other agents; the orchestrator does |
| 7 | External gates: **preconditions** | Each task records `kind` (§4) and, for `build`, `spec` (the spec it implements) in `state.json`. Before dispatching a task of kind `before`, check each matching gate. **Met** = the file exists, `status: accepted`, its `digest` equals the artifact's current digest, **and** `decisions.md` holds the human's confirmation of that gate id and digest (a quote or reference, recorded the first time the human confirms, as for sign-off). The confirmation is persisted, so it survives resume. Not met → the task and its dependents are `blocked` with `blockedBy: external:<id>`, **no retry consumed**. Other ready tasks continue; the run pauses only when no task is ready. On every loop iteration and every resume, blocked tasks are re-checked; when the gate is met they return to `pending`. A stale gate (new digest) blocks dependent tasks again. The team never writes acceptance files. **A phase skill run on its own in contract mode** checks the gates for its own task kind first, and refuses with the reason if any is not met |
| 8 | Decisions | If `decisions` is set, each new decision is a **new** record in `decisions.dir` with `proposed_status`. Specialists never edit existing records or set `accepted_status`; only humans do. The scribe (or the orchestrator inline in the CLI) **adds** a line to `decisions.md` for each record: `[<id>](<path>) — <status> — <one-line summary>`. **Everything `decisions.md` already holds stays:** the full sign-off record and waivers, exactly as the safety floors require |
| 9 | Change requests | A change to anything under `protected`, or to an accepted decision record, is raised as a new Proposed record. The affected story is `blocked` (`blockedBy: decision:<id>`) until a human accepts or rejects it; no retry consumed |
| 10 | `path-check` gate | **Before each dispatch,** record a baseline: the `HEAD` commit, `git status --porcelain=v1 -uall`, and a SHA-256 of every path that is changed or untracked at that moment. **After the task,** candidates = `git diff --name-only <baseline HEAD>` ∪ the untracked paths now ∪ the baseline's changed paths (renames: both names). A candidate **was changed by the task** only if its current content (or absence) differs from its baseline content: the recorded hash for paths changed at baseline, otherwise the blob at `<baseline HEAD>`. Pre-existing dirty files the task left alone don't count. **Fail** if a task-changed path is under `frozen` (no exception), under `protected`, or in `decisions.dir`. The one exception: a **new** file in `decisions.dir`, not under `frozen`, whose status is `proposed_status`. If `path_check` is set, run it too; both must pass. Specialists still add their own unit and integration tests outside `frozen` |
| 11 | Deliverables | Specialists write deliverables to `contract.paths` where set; the `inbox/` file keeps a short pointer. `.copilot-tracking/` stays the trace; `state.json` stays canonical for tasks and resumption |
| 12 | Result | Standard Result block, plus `- Contract: <rules applied; gates met or blocked>` |
| 13 | Artifact identity | The digest rules and placeholders from §4.1, written out in full: file digest; canonical folder manifest; the release candidate SHA recorded in `state.json.signoff.artifact` before `release-acceptance` is evaluated; `{spec}` and `{version}` |

Body has these **13** sections. Other skills cite them by name (e.g., "`ait-contract-mode` › Artifact identity").

Limits stay with the host (CLI session limits such as `--max-ai-credits`, which is a soft cap) and the existing retry rule. Contract mode adds none.

## 8. Deliberately **not** changed (and why)

| Item | Why not |
|---|---|
| `handoffs` and `agents` in agent frontmatter | VS Code Local features that are part of the plugin's design; the CLI ignores them |
| The `agent` tool on `ait-architect` | Needed for the VS Code Local subagent graph; contract mode restricts dispatch in the skill (§4.2 §6) |
| `infer` / `disable-model-invocation` on the orchestrator | Would change how existing users reach the orchestrator; no benefit to this release |
| `model-policy` / `modelPolicy` | Not forwarded for plugin agents in VS Code; not portable |
| Automatic reviewer selection | Selecting a model per dispatch isn't portable across surfaces; the human re-runs the review (G4) |
| Run limits in the config | Skills can't enforce time or credits; hosts already offer session limits |
| The default lifecycle, gates, tracking files, scribe and sign-off text | Guarantee 1 |
